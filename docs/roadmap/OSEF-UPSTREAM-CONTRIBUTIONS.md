# OSEF — Registre de contributions upstream Payment Engineering

> **Registre à amorcer.** Aucune contribution, PR fusionnée ou participation des ingénieurs n'est présumée.

## Finalité

Convertir la réalisation des labs en contributions vérifiables aux projets Mojaloop, Apache Fineract, Mifos Payment Hub EE, jPOS, Tazama, FINOS/FDC3 et outils associés.

## Processus

1. **Identifier** : relever problème concret, dépôt upstream officiel, licence, mainteneur et issue éventuelle.
2. **Reproduire** : créer un cas minimal avec versions et données synthétiques.
3. **Proposer** : ouvrir une issue upstream ou discuter du correctif conformément aux consignes du projet.
4. **Contribuer** : déposer test, documentation ou patch ; relier à un lab OSEF et à un SHA.
5. **Suivre** : statut (proposé, ouvert, en revue, accepté, refusé, clos), commentaires et lien upstream.
6. **Capitaliser** : rétroporter si nécessaire les retours techniques dans le catalogue et la formation interne.

### Types de contributions recherchées

- Mojaloop : non-régression timeout, idempotence, simulateurs, documentation d'intégration.
- Fineract : tests de transferts, API, erreurs, documentation bancaire.
- Mifos Payment Hub EE : adaptateurs, résilience, tests contractuels.
- jPOS : cas ISO 8583 fictifs et compatibilité de build.
- Tazama : jeux de tests, intégration, Helm, performance, documentation.
- FINOS/FDC3 : tests d'interopérabilité d'applications financières fictives.

## Conditions de preuve

Un commentaire GitHub OSEF ne prouve pas une contribution externe. Conserver un lien vers une issue/PR réelle dans le dépôt upstream, avec statut vérifié. Ne jamais annoncer qu'une contribution est acceptée tant que le dépôt upstream ne le confirme.

## Indicateurs mensuels proposés

Nombre d'issues upstream documentées ; cas de reproduction publiés ; PR soumises ; PR fusionnées ; délais de revue ; labs améliorés à partir des retours. Les indicateurs restent vides jusqu'à collecte.
